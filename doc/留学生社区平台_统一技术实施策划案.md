# 留学生社区平台统一技术实施策划案

## 一、文档目标
本文件用于统一留学生社区平台的前端、后端与数据库实施方案，作为项目开发、联调、测试、部署和后续迭代的执行依据。

本策划案重点解决以下问题：

1. 项目的整体技术架构如何设计。
2. 前端、后端、数据库分别承担什么职责。
3. 模块边界、接口规范、数据结构如何统一。
4. 如何安排开发阶段、联调流程、测试策略与上线方案。

## 二、项目技术结论

### 2.1 客户端
1. 前端框架使用 Flutter。
2. 客户端同时支持 Android 端与 iOS 端。
3. 移动端采用统一代码基座，减少双端重复开发。

### 2.2 服务端
1. 后端编程语言使用 Kotlin。
2. 项目后端框架使用 Spring Boot。
3. 后端采用 RESTful API 为主，聊天服务可补充 WebSocket 通信。

### 2.3 数据存储
1. 主数据库使用 MySQL。
2. 缓存建议使用 Redis。
3. 图片、认证文件等资源建议使用对象存储。

## 三、业务目标与 MVP 范围

### 3.1 核心业务目标
平台需要支撑以下主链路：

注册登录 -> 完善资料 -> 提交认证 -> 获取匹配推荐 -> 发起聊天 -> 浏览社区 -> 获取信息 -> 长期留存

### 3.2 MVP 包含模块
1. 账号与登录
2. 用户资料与标签
3. 学生认证
4. 匹配推荐
5. 私聊聊天
6. 社区发帖与评论
7. 信息中心
8. 举报与拉黑
9. 管理后台基础能力

### 3.3 MVP 暂不包含
1. 音视频通话
2. 会员支付
3. 复杂推荐算法
4. 广告投放系统
5. 群聊与大型社区群组
6. 多国家多地区独立运营后台

## 四、整体技术架构

### 4.1 架构分层
建议采用四层结构：

1. 客户端展示层：Flutter App
2. 服务接口层：Spring Boot API
3. 业务服务层：用户、匹配、聊天、社区、内容、审核等业务模块
4. 数据存储层：MySQL + Redis + 对象存储

### 4.2 核心模块图
1. 前端 App：负责页面展示、交互逻辑、状态管理、接口调用、本地缓存
2. API 网关层：负责鉴权、日志、限流、路由分发
3. 用户服务：账号、资料、标签、认证、隐私设置
4. 匹配服务：推荐逻辑、推荐记录、用户反馈
5. 消息服务：会话、消息、未读计数、通知
6. 社区服务：帖子、评论、点赞、收藏、搜索
7. 内容服务：信息中心文章、分类、更新记录
8. 风控审核服务：举报、封禁、敏感词、审核记录
9. 管理后台服务：内容管理、用户审核、数据看板

### 4.3 架构目标
1. 单体优先，模块清晰。
2. 先保证可交付，再逐步优化扩展性。
3. 聊天、社区、推荐等模块必须为后续扩展预留边界。

## 五、前端实施方案

## 5.1 前端技术栈
1. 框架：Flutter
2. 状态管理：推荐 Riverpod
3. 路由管理：GoRouter
4. 网络请求：Dio
5. 本地安全存储：flutter_secure_storage
6. 普通缓存：SharedPreferences 或 Hive
7. 国际化：Flutter Intl
8. 图片缓存：cached_network_image

## 5.2 前端架构建议
建议采用以下目录分层：

1. `core`
2. `shared`
3. `features`
4. `services`
5. `routes`
6. `l10n`

### 目录职责
1. `core`：主题、全局配置、异常处理、常量、工具类
2. `shared`：基础组件、通用模型、通用状态组件
3. `features`：按业务拆分页面、状态、仓储
4. `services`：网络层、上传服务、推送服务
5. `routes`：路由配置与守卫
6. `l10n`：多语言资源

## 5.4 前端状态管理策略

### 全局状态
1. 登录态
2. 当前用户
3. 语言设置
4. 未读消息数
5. 应用配置

### 业务状态
1. 推荐列表状态
2. 帖子流状态
3. 会话列表状态
4. 文章列表状态
5. 认证提交流程状态

### 状态原则
1. 所有异步请求统一为 loading、success、empty、error 四态。
2. 页面不直接写网络逻辑，统一走 repository。
3. 错误提示需区分网络错误、鉴权错误、业务错误。

## 5.5 前端非功能要求
1. Android 与 iOS 保持一致页面结构与交互主流程。
2. 所有文案支持中、韩、英扩展。
3. 长列表需支持分页与下拉刷新。
4. 图片上传需压缩，避免流量与性能问题。
5. 关键链路必须埋点。

## 六、后端实施方案

## 6.1 后端技术栈
1. 语言：Kotlin
2. 框架：Spring Boot
3. ORM：Spring Data JPA 或 MyBatis Plus 二选一
4. 安全框架：Spring Security + JWT
5. 参数校验：Jakarta Validation
6. API 文档：SpringDoc OpenAPI
7. 缓存：Redis
8. 构建工具：Gradle Kotlin DSL

## 6.2 后端工程结构建议
建议按模块化单体组织项目：

1. `common`
2. `auth`
3. `user`
4. `verification`
5. `match`
6. `chat`
7. `community`
8. `content`
9. `report`
10. `admin`

### 模块职责
1. `common`：统一响应体、异常处理、工具类、枚举、通用配置
2. `auth`：注册、登录、验证码、Token 刷新
3. `user`：用户资料、标签、状态、隐私设置
4. `verification`：学生认证提交、审核、记录
5. `match`：匹配规则、推荐结果、跳过反馈
6. `chat`：会话、消息、未读数、系统通知
7. `community`：帖子、评论、点赞、收藏、板块
8. `content`：信息中心文章与分类
9. `report`：举报、拉黑、风控
10. `admin`：后台用户、审核、运营管理

## 6.3 后端接口风格
1. 统一使用 `/api/v1` 前缀。
2. 成功响应结构统一。
3. 错误码统一管理。
4. 列表接口统一分页结构。
5. 上传接口返回标准文件 URL 与资源 ID。

### 建议响应格式
```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 分页格式
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 20,
    "total": 120,
    "hasNext": true
  }
}
```

## 6.4 后端鉴权与权限
1. App 用户使用 JWT 鉴权。
2. 后台管理端使用后台账号体系与角色权限。
3. 普通用户与管理员权限分离。
4. 敏感接口需校验账号状态、认证状态、封禁状态。

### 后台角色建议
1. 超级管理员
2. 内容审核员
3. 用户审核员
4. 运营编辑

## 6.5 后端核心业务规则

### 注册登录
1. 手机号或邮箱至少绑定一种。
2. 同一账号不可重复注册。
3. 多次失败登录需触发风控。

### 资料与标签
1. 首次使用必须完成最低资料集。
2. 用户状态标签默认 24 小时过期。
3. 标签配置由后台统一管理。

### 认证审核
1. 用户可提交学校邮箱或证件材料。
2. 驳回必须记录原因。
3. 审核记录必须留痕。

### 匹配推荐
1. 基于学校、语言、标签、状态、活跃度生成推荐。
2. 已跳过、已拉黑用户不再推荐。
3. 推荐结果需落库，便于追踪转化。

### 聊天
1. 会话需绑定双方用户。
2. 被拉黑后禁止继续发消息。
3. 消息记录保存最近 90 天或按业务策略存档。

### 社区
1. 发帖需进行敏感词检测。
2. 匿名帖子对普通用户匿名，对后台可追踪。
3. 被举报内容保留审计副本。

### 信息中心
1. 文章需要记录来源和更新时间。
2. 下线文章保留历史状态，不做物理删除。

## 6.6 后端非功能要求
1. 核心接口需记录访问日志。
2. 上传接口需做类型、大小、安全校验。
3. 关键接口需限流。
4. 审核与封禁操作需保留操作日志。
5. 数据库操作需避免 N+1 查询与长事务。

## 七、数据库实施方案

## 7.1 数据库选型
主库使用 MySQL 8.x，字符集建议使用 `utf8mb4`，排序规则建议使用支持多语言的通用规则。

## 7.2 数据库设计原则
1. 先满足业务正确性，再考虑复杂分库分表。
2. 所有主表使用自增 ID 或雪花 ID，项目中统一。
3. 表字段命名保持统一风格。
4. 关键状态字段必须枚举化。
5. 所有表必须包含创建时间、更新时间。

## 九、前后端联调规则

### 9.1 联调基本原则
1. 所有接口先定义文档，再进入开发。
2. 后端优先提供 Swagger 文档与 Mock 数据。
3. 前端以统一响应体开发，不允许每个接口单独适配风格。

### 9.2 字段约定
1. 状态字段统一枚举值。
2. 时间字段统一 ISO 8601 或项目固定格式。
3. 分页参数统一 `page`、`pageSize`。
4. 布尔值不使用 0/1 和 true/false 混用。

### 9.3 上传与媒体约定
1. 上传接口返回 `fileId` 与 `url`。
2. 前端展示图走 CDN 或对象存储公网地址。
3. 敏感材料走受控访问链接。

## 十一、安全与隐私策略

### 11.1 数据安全
1. 密码必须加密存储。
2. JWT 需要设置过期时间与刷新机制。
3. 认证材料与举报内容做最小权限访问控制。
4. 敏感操作需记录操作者与时间。

### 11.2 内容安全
1. 发帖与评论接入敏感词过滤。
2. 举报内容支持人工复核。
3. 封禁与删除策略需可追踪。

### 11.3 隐私保护
1. 用户敏感资料支持分级可见。
2. 聊天记录与认证文件不得对普通后台角色开放。
3. 日志中避免输出明文敏感信息。
