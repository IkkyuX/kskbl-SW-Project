# 留学生社区平台开发用策划案

## 一、文档目的
本策划案用于指导留学生社区平台的产品设计、技术实现与项目管理，面向产品经理、设计师、前后端开发、测试和运营同学使用。与商业策划案不同，本文件重点回答以下问题：

1. 第一版产品到底做什么，不做什么。
2. 每个功能模块的目标、流程、规则和边界是什么。
3. 需要哪些核心页面、接口、数据表和后台能力。
4. 如何拆分版本、安排开发顺序和验收标准。

## 二、项目定义

### 2.1 项目名称
留学生社区平台

### 2.2 项目目标
构建一款面向在韩留学生的移动端社区产品，帮助用户完成以下核心任务：

1. 建立可信身份并找到相似背景或相同需求的人。
2. 获取高频、可靠、可搜索的校园与生活信息。
3. 通过聊天、发帖和活动逐步建立稳定关系。

### 2.3 产品形态
1. 移动端 App：iOS / Android
2. 管理后台：Web
3. 服务端：API + 管理服务 + 数据服务

### 2.4 MVP 成功标准
若上线后 8 周内达到以下指标，则视为 MVP 验证基本成功：

1. 注册用户数达到 500
2. 完成资料填写率不低于 70%
3. 完成学生认证率不低于 40%
4. 匹配后发起聊天率不低于 30%
5. 7 日留存率不低于 25%
6. 周发帖用户占比不低于 15%

## 三、目标用户与使用场景

### 3.1 目标用户
1. 刚到韩国 0 至 12 个月的留学生
2. 准备入学或刚收到录取通知的潜在留学生
3. 已在韩就读、愿意帮助新人的高年级留学生

### 3.2 核心使用场景
1. 新生入境前，查找签证、住宿、电话卡、银行卡等信息。
2. 到校后，希望认识同校、同专业、同语种或同兴趣的朋友。
3. 在遇到选课、租房、兼职、办证等问题时，希望快速获取可信答案。
4. 平时需要找饭搭子、学习搭子、活动搭子。
5. 参加线下活动并沉淀长期社交关系。

## 四、产品范围定义

### 4.1 MVP 包含范围
1. 注册登录

## 五、功能模块说明

## 5.1 账号与登录模块

### 功能目标
支持用户快速注册、登录，并建立基础身份。

### 功能清单
1. 邮箱注册
2. 手机号注册
3. 验证码登录
4. 忘记密码与密码重置
5. 登录态维护
6. 设备绑定与异常登录提醒

### 关键规则
1. 手机号和邮箱至少绑定一种。
2. 同一手机号不可重复注册多个账号。
3. 被封禁账号禁止重新登录。
4. 用户首次登录后必须进入资料完善流程。

### 验收标准
1. 注册流程不超过 2 分钟。
2. 登录失败有明确错误提示。
3. Token 过期后可安全刷新。

## 5.2 用户资料与标签模块

### 功能目标
为匹配、推荐和社区互动提供用户画像基础。

### 资料字段
1. 昵称
2. 头像
3. 性别
4. 国籍
5. 使用语言
6. 学校
7. 专业
8. 年级
9. 到韩时间
10. 自我介绍

### 标签类型
1. 固定标签：学校、专业、学历、语言、国籍
2. 兴趣标签：运动、游戏、旅行、学习、聚餐等
3. 场景标签：找室友、找饭搭子、找学习搭子、找人聊天、找活动
4. 状态标签：刚到韩国、选课中、找兼职中、心情低落

### 关键规则
1. 用户首次注册至少选择 5 个标签。
2. 状态标签可主动切换，默认 24 小时后自动失效。
3. 敏感字段支持公开、仅匹配可见、仅自己可见三档权限。

### 验收标准
1. 用户可在 2 分钟内完成初始化资料填写。
2. 标签可由后台灵活配置，无需发版。

## 5.3 学生认证模块

### 功能目标
提升社区真实性和用户信任。

### 功能清单
1. 提交认证材料
2. 查看审核状态
3. 审核通过与驳回通知
4. 重新提交认证

### 认证方式
1. 学校邮箱验证
2. 学生证上传
3. 录取通知书上传

### 审核状态
1. 未认证
2. 审核中
3. 已通过
4. 已拒绝
5. 已过期

### 关键规则
1. 认证资料仅审核员可见。
2. 驳回需填写原因。
3. 连续多次提交失败需触发人工关注。

### 验收标准
1. 用户能清晰看到审核进度与结果。
2. 后台能完成批量审核与记录留痕。

## 5.4 匹配模块

### 功能目标
帮助用户快速找到合适的社交对象。

### MVP 匹配输入
1. 学校
2. 专业
3. 语言
4. 兴趣标签
5. 场景标签
6. 当前状态
7. 活跃时间段

### MVP 匹配规则
1. 同校优先
2. 同语言优先
3. 场景标签一致优先
4. 近期活跃用户优先
5. 已跳过和已拉黑用户不再推荐

### 功能清单
1. 推荐列表
2. 用户卡片详情
3. 匹配理由展示
4. 一键打招呼
5. 跳过与不感兴趣反馈

### 边界说明
1. MVP 不做无限刷卡式推荐。
2. MVP 不做复杂机器学习模型。
3. 推荐刷新频率每日 1 至 3 次即可。

### 验收标准
1. 每个用户每天至少获得 5 个有效推荐。
2. 匹配理由必须可解释。

## 5.5 聊天模块

### 功能目标
承接匹配结果，形成真实互动。

### MVP 功能清单
1. 私聊会话列表
2. 文本消息发送
3. 图片消息发送
4. 系统问候语模板
5. 未读消息数
6. 举报与拉黑
7. 删除会话

### 关键规则
1. 只有匹配成功或主动打招呼成功后才可发起聊天。
2. 被拉黑后双方无法继续通信。
3. 举报记录需同步至后台审核队列。

### 非功能要求
1. 消息到达时延尽量控制在 1 秒级别。
2. 历史消息支持最近 90 天查询。
3. 聊天记录需要具备审计能力，但需保护隐私。

### 验收标准
1. 消息发送、接收、重试流程稳定。
2. 异常断网恢复后不会重复发消息。

## 5.6 社区模块

### 功能目标
沉淀用户经验，提升留存与内容价值。

### 板块设计
1. 新生报到
2. 学习选课
3. 租房生活
4. 打工兼职
5. 交友活动
6. 匿名树洞

### MVP 功能清单
1. 发帖
2. 编辑与删除帖子
3. 评论
4. 点赞
5. 收藏
6. 举报
7. 帖子搜索
8. 分类筛选

### 内容字段
1. 标题
2. 正文
3. 图片
4. 板块
5. 标签
6. 是否匿名

### 关键规则
1. 匿名仅对普通用户匿名，对后台可追踪。
2. 发帖需经过敏感词和风控检测。
3. 被删除内容保留审计副本。

### 验收标准
1. 发帖路径清晰，支持图文混排。
2. 社区首页可按推荐、最新、关注切换。

## 5.7 信息中心模块

### 功能目标
提供结构化、可靠的信息内容。

### 内容分类
1. 入境准备
2. 学校报到
3. 签证与证件
4. 住宿与交通
5. 银行与通信
6. 奖学金与实习

### MVP 功能清单
1. 分类浏览
2. 关键词搜索
3. 文章详情
4. 收藏
5. 来源与更新时间展示

### 关键规则
1. 所有文章需带来源。
2. 文章需带最后更新时间。
3. 过期内容需支持下线或标红提醒。

### 验收标准
1. 搜索结果可按分类筛选。
2. 文章详情页加载清晰，支持多语言字段扩展。

## 5.8 举报、风控与安全模块

### 功能目标
保护社区秩序与用户安全。

### 功能清单
1. 举报用户
2. 举报帖子
3. 举报消息
4. 拉黑用户
5. 敏感词过滤
6. 审核日志

### 关键规则
1. 举报需选择原因并支持补充说明。
2. 同一对象短时间内被多次举报应自动提级。
3. 高风险账号可限制发言、限制匹配或封禁。

### 验收标准
1. 举报链路完整，处理状态可追踪。
2. 后台可查看举报对象上下文。

## 5.9 管理后台模块

### 功能目标
让运营和审核团队可以独立维护平台。

### MVP 后台页面
1. 登录页
2. 用户列表
3. 认证审核页
4. 内容审核页
5. 举报处理页
6. 标签配置页
7. 信息中心内容管理页
8. 数据总览页

### 关键能力
1. 用户搜索与筛选
2. 审核通过、驳回、封禁
3. 内容删除、隐藏、置顶
4. 标签增删改
5. 文章创建、编辑、下线
6. 操作日志记录

### 验收标准
1. 后台权限分级明确。
2. 审核操作有审计记录。

## 六、核心用户流程

### 6.1 新用户主流程
下载 App -> 注册登录 -> 完善资料 -> 选择标签 -> 提交认证 -> 查看推荐 -> 发起聊天 -> 浏览社区 -> 收藏信息

### 6.2 社区互动流程
进入社区首页 -> 选择板块 -> 浏览帖子 -> 评论或点赞 -> 收藏帖子 -> 举报不良内容

### 6.3 信息获取流程
进入信息中心 -> 选择分类或搜索关键词 -> 查看文章 -> 收藏或分享 -> 返回继续浏览

### 6.4 后台审核流程
审核员登录 -> 查看待处理队列 -> 审核认证或举报 -> 记录处理结果 -> 触发站内通知

## 八、技术架构建议

### 8.1 推荐技术选型
1. 客户端：Flutter
2. 服务端：Spring Boot 或 FastAPI
3. 数据库：PostgreSQL
4. 缓存：Redis
5. 消息服务：WebSocket 或第三方 IM
6. 对象存储：云存储服务
7. 后台：React + Ant Design 或 Vue + Element Plus

### 8.2 服务拆分建议
1. 用户服务
2. 认证服务
3. 匹配服务
4. 消息服务
5. 社区服务
6. 内容服务
7. 审核与风控服务
8. 后台管理服务

### 8.3 环境规划
1. 开发环境
2. 测试环境
3. 预发布环境
4. 生产环境

### 8.4 非功能要求
1. 接口鉴权统一
2. 日志可追踪
3. 关键接口具备限流能力
4. 图片上传需压缩与安全校验
5. 敏感数据需加密存储

## 十三、风险与技术注意事项

### 13.1 冷启动风险
推荐依赖用户画像和活跃用户数量，初期需要运营导入种子用户，不能只依赖自然增长。

### 13.2 聊天服务复杂度
即时消息模块开发和运维成本高，若团队经验不足，可优先接入成熟第三方服务。

### 13.3 内容审核压力
社区与匿名内容容易带来违规风险，MVP 阶段必须保留人工审核能力。

### 13.4 多语言维护成本
多语言文本量大，需提前设计国际化资源管理方案，避免后期重构。

### 13.5 个人信息保护
认证资料、聊天记录和举报信息均为敏感数据，必须做最小权限访问控制与脱敏处理。

## 十五、结论
本开发用策划案的核心原则是：先做闭环，再做复杂；先做可信，再做规模；先做可运营，再做可商业化。第一阶段必须把注册、资料、认证、匹配、聊天、社区、信息中心和后台审核这条主链路打通，确保产品从第一天开始就是一个可用、可控、可迭代的留学生社区平台。
